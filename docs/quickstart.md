# Быстрый старт

> [!NOTE]
> Релиз включает все четыре платформы: `linux-x64`, `linux-arm64`, `darwin-arm64`
> (macOS на Apple Silicon), `windows-x64`.

Эта страница описывает проверенный путь установки **скомпилированного клиентского
артефакта**: без `git clone`, без доступа к приватному репозиторию исходников, без
`GITHUB_TOKEN`, без `bun`/`node` на машине. Установщик внутри архива сам скачивает и
криптографически проверяет бинарь ядра.

## 1. Скачать архив для своей платформы

Со страницы Releases этого репозитория:

```bash
curl -fsSLO https://github.com/pyramidheadshark/scaffold/releases/latest/download/scaffold-linux-x64.tar.gz
```

Поддерживаемые `<PLATFORM>`: `linux-x64`, `linux-arm64`, `darwin-arm64`,
`windows-x64`. На Windows `install.sh` запускается из Git Bash (штатно ставится вместе
с Git for Windows) — определяет платформу автоматически и качает `.exe`-ассет; отдельного
установщика не требуется. Windows-бинарь пока не имеет Authenticode-подписи (проверка
целостности релиза через Ed25519+SHA-256 — обязательна и работает на всех платформах
одинаково, см. шаг 3).

## 2. Распаковать

```bash
# подставьте имя скачанного архива своей платформы (шаг 1)
mkdir scaffold && tar -xzf scaffold-linux-x64.tar.gz -C scaffold
cd scaffold
```

В архиве — уже скомпилированный бинарь `scaffold`, данные конфигурации (роли, скиллы,
профили безопасности), `install.sh`, публичный ключ проверки подписи (`keys/minisign.pub`)
и юридическое сопровождение (`LICENSE`, `LICENSE-BINARY.md`, `THIRD_PARTY_NOTICES.md` — условия использования именно этого бинаря смотри в `LICENSE-BINARY.md`). Исходников
TypeScript-ядра в архиве нет.

## 3. Установить

```bash
export SCAFFOLD_KERNEL_REPO=pyramidheadshark/scaffold-kernel
bash install.sh
```

⚠ **Экспорт переменной обязателен.** `install.sh` по умолчанию тянет релиз ядра из
`pyramidheadshark/pi-scaffold` — это приватный репозиторий исходников владельца, и без
переменной выше анонимная установка упрётся в 404 и попросит `gh auth`/`GITHUB_TOKEN`.
`SCAFFOLD_KERNEL_REPO` указывает на отдельный публичный репозиторий с готовыми
бинарями ядра — `pyramidheadshark/scaffold-kernel`. Если вы форкаете это
распространение под своим именем — задайте здесь собственный репозиторий с релизами
ядра.

⚠ **`scaffold update` и откат (ниже) читают ту же переменную заново при каждом
запуске** — она не сохраняется установщиком. Если не добавить её в свой профиль
шелла, обновление в новом терминале снова упрётся в приватный репозиторий:

```bash
echo 'export SCAFFOLD_KERNEL_REPO=pyramidheadshark/scaffold-kernel' >> ~/.bashrc   # bash
echo 'export SCAFFOLD_KERNEL_REPO=pyramidheadshark/scaffold-kernel' >> ~/.zshrc    # zsh
set -Ux SCAFFOLD_KERNEL_REPO pyramidheadshark/scaffold-kernel                      # fish
```

Скрипт:

1. Скачивает подписанный релиз ядра под вашу платформу.
2. Скачивает `manifest.json` + `manifest.json.minisig` из того же релиза.
3. Проверяет Ed25519-подпись манифеста и сверяет SHA-256 контрольную сумму скачанного
   бинаря ядра с записью в манифесте.
4. Только после успешной проверки — раскладывает бинарь и создаёт симлинк
   `~/.local/bin/scaffold`.

Проверка подписи — не опциональный шаг: при отсутствии `minisign`/`jq` или при ошибке
проверки установка останавливается с понятным сообщением, а не продолжает молча.

Требуются `curl`, `minisign`, `jq`:

```bash
sudo apt install minisign jq      # Debian/Ubuntu, WSL
sudo dnf install minisign jq      # Fedora
brew install minisign jq          # macOS
```

## 4. Проверить установку

```bash
export PATH="$HOME/.local/bin:$PATH"  # если install.sh предупредил, что ~/.local/bin не в PATH
scaffold --version     # версия CLI и ядра одной строкой
scaffold doctor         # health-check: PATH, provider-auth, число загруженных плагинов
```

Для новых терминалов install.sh уже показал команду добавления `~/.local/bin` в
профиль вашего шелла (bash/zsh/fish) — строка выше нужна только для проверки в
текущей сессии сразу после установки.

## 5. Настроить провайдера модели

Самый быстрый способ — OpenAI Codex через OAuth, без отдельного API-ключа:

```bash
scaffold
# внутри TUI: /login → откроется браузер
```

Также поддерживаются OpenRouter и DS Lab через переменные окружения
(`OPENROUTER_API_KEY`, `DSLAB_API_KEY`). Без ключей TUI сам предложит настройку в
Settings при первом запуске.

## 6. Первая задача

`scaffold` без аргументов — основной, целевой режим работы: интерактивный TUI, где
роль `prime` ведёт диалог, задаёт уточняющие вопросы при неопределённой постановке,
формирует план и ждёт подтверждения, прежде чем менять код.

Опишите задачу текстом прямо в TUI:

```
> В проекте нестабильно ведёт себя одна из функций — иногда работает, иногда нет.
> Разберись и предложи план.
```

Если формулировка неопределённая — это не баг, а часть протокола: `prime` обязан
задать уточняющие вопросы, прежде чем что-либо менять.

## Обновление

```bash
cd scaffold && scaffold update
scaffold --version   # проверить, что версия сменилась
```

## Откат

Если после обновления что-то сломалось — конкретная версия ядра ставится явно:

```bash
SCAFFOLD_KERNEL_REPO=pyramidheadshark/scaffold-kernel SCAFFOLD_VERSION=<предыдущая-версия> bash install.sh
```

Проверка подписи при откате не отключается так же, как и при первой установке. Конфиги,
ключи провайдеров и правила проекта установщик не трогает ни при обновлении, ни при откате.
